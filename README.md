# 성적 CSV 로더와 명세 기반 테스트 실습

## ① 무엇을 하나요 (What)

성적 CSV 파일을 읽어 유효한 이름·점수 목록과, 잘못된 데이터의 제외 기록을 반환합니다.

- 함수: `load_scores(path)`
- 반환 형식: `(kept, skipped)`
- `kept`: `(이름, 정수 점수)` 튜플의 목록
- `skipped`: `(줄번호, 원본 내용, 제외 사유)` 튜플의 목록

점수는 0 이상 100 이하의 정수만 허용합니다.
같은 이름이 여러 번 나와도 동명이인일 수 있으므로 유효한 행은 모두 유지합니다.
빈 줄은 제외 기록 없이 무시합니다.

## ② 왜 만들었나요 (Why)

성적 CSV에 점수 누락, 범위 밖 점수, 잘못된 열 개수 등이 섞여 있어 이를 구분하는 프로그램의 동작을 확인하고 싶었습니다.
정상 입력뿐 아니라 오류 입력과 경계값도 자동으로 검사하고, AI에게 코드와 명세를 각각 제공했을 때 테스트 결과가 어떻게 달라지는지 비교하기 위해 실습했습니다.

## ③ 어떻게 쓰나요 (How)

### 준비

Python이 설치된 환경에서 저장소를 내려받고,
`load_scores.py`가 있는 폴더에서 터미널을 엽니다.

프로그램 실행에는 파이썬 표준 라이브러리만 사용합니다.
테스트를 실행하려면 다음 패키지를 설치합니다.

```bash
python -m pip install pytest pytest-cov
```

### 실행

```bash
python load_scores.py scores.csv
```

### 실제 확인한 실행 결과

현재 로컬에서 실행한 `scores.csv`는 다음과 같이 처리됐습니다.

```text
읽은 줄 : 5개
  김하나 88
  최,네번 77
  김하나 91
  윤보람 64
  서한별 95
건너뛴 줄 : 5개
  3행  이두리,105   ← 점수가 0~100 밖
  4행  박세찬,   ← 점수가 비어 있음
  7행  정오름,-5   ← 점수가 0~100 밖
  8행  한겨울,결석   ← 점수가 정수가 아님
  9행  장미르,72,비고없음   ← 열 개수가 2가 아님
```

### CSV 입력에 관한 주의

실행에 사용한 로컬 파일에는 쉼표가 포함된 이름이 다음처럼 저장되어 있습니다.

```csv
"최,네번",77
```

이 입력은 CSV 규칙상 이름과 점수의 두 열로 읽힙니다.

반면 따옴표가 없는 다음 입력은 세 열로 읽혀 제외됩니다.

```csv
최,네번,77
```

실습 중 첨부본과 로컬 파일 사이에서 해당 행의 따옴표 유무 차이를 확인했습니다.
위 실행 결과는 로컬 파일 기준입니다.

## ④ 어떻게 테스트하나요

### 기본 검증

```bash
python -m pytest test_load_scores.py -v
```

실제 확인한 결과:

```text
12 passed in 0.08s
```

검사 항목:

- 정상 학생 데이터 읽기
- 빈 줄 무시
- 따옴표로 감싼 쉼표 포함 이름 처리
- 없는 파일에서 FileNotFoundError 발생
- 헤더만 있는 파일에서 빈 목록 두 개 반환
- 0점과 100점 포함, 101점 제외
- 열 개수 오류
- 이름 누락
- 점수 누락
- 정수가 아닌 점수

### 커버리지

```bash
python -m pytest test_load_scores.py --cov=load_scores --cov-report=term-missing
```

실제 측정 결과:

```text
Name             Stmts   Miss  Cover   Missing
----------------------------------------------
load_scores.py      45      9    80%   77-86
----------------------------------------------
TOTAL               45      9    80%
```

기본 8개 케이스의 커버리지는 60%였으며,
오류 입력 네 가지를 추가한 뒤 12개 케이스, 80%로 상승했습니다.

77-86행은 파일을 직접 실행할 때 사용하는 명령줄 인자 처리 및 출력 부분입니다.
함수를 불러오는 현재 테스트에서는 실행되지 않았습니다.

커버리지는 코드 실행 범위에 대한 지표이며,
수치가 높다고 모든 동작의 정확성이 보장되는 것은 아닙니다.

### 의도적인 실패 확인

쉼표 이름 테스트의 기대 점수만 88점에서 89점으로 바꾸자
`1 failed, 11 passed`가 나왔습니다.
기대값을 88점으로 복구한 뒤 `12 passed`를 다시 확인했습니다.

### AI 테스트 A/B 비교

각 테스트 파일을 개별 실행합니다.

```bash
python -m pytest test_ai_A.py -v
python -m pytest test_ai_B.py -v
```

커버리지 측정:

```bash
python -m pytest test_ai_A.py --cov=load_scores --cov-report=term-missing
python -m pytest test_ai_B.py --cov=load_scores --cov-report=term-missing
```

| 항목 | A: 구현 코드 제공 | B: 명세 제공 |
| --- | --- | --- |
| 실행 케이스 | 20개 | 30개 |
| 통과 | 20개 | 29개 |
| 실패 | 0개 | 1개 |
| 커버리지 | 80% | 80% |
| 미실행 줄 | 77-86 | 77-86 |

B의 실패는 제외 기록에 CSV 원문의 따옴표가 보존되는지에 관한 차이입니다.

- B의 기대: `"잘못된, 이름",abc`
- 구현의 반환: `잘못된, 이름,abc`

구현은 CSV를 해석한 값을 쉼표로 다시 연결하므로 원래 따옴표를 보존하지 않습니다.
이 결과는 명세의 ‘원본줄’ 보존 범위를 명확히 할 필요가 있음을 보여 줍니다.
비교 실험 결과를 보존하기 위해 해당 테스트는 수정하지 않았습니다.

B에 사용한 명세서는 10주차에 독립적으로 작성한 문서가 아니라,
11주차 배포 파일의 명세 주석을 바탕으로 사후 보완한 문서입니다.

### 논리 오류 검출 실험

```bash
python -m pytest test_bug3_logic.py -v
```

실제 결과:

```text
12 failed, 15 passed in 0.13s
```

이 테스트는 의도적으로 버그가 남아 있는 `bug3_logic.py`를 검사합니다.

- `find_max`: 마지막 원소를 검사하지 않는 문제
- `count_pass`: 기준과 같은 점수를 합격에서 제외하는 문제

AI는 입력 `[70, 85, 60, 95]`에 대해 최고점 95, 합격자 4명을 기대값으로 정했습니다.
이번 조건에서는 구현의 잘못된 결과를 정답으로 굳히지 않고 버그를 검출했습니다.

### 전체 실행 시 주의

옵션 없이 `python -m pytest`를 실행하면 비교 실험용 테스트도 함께 수집됩니다.
따라서 보존한 B의 실패와 논리 오류 검출 테스트의 실패가 나타날 수 있습니다.

성적 로더의 기본 검증 결과를 확인하려면
`test_load_scores.py`를 지정해서 실행하세요.

## ⑤ 파일 구성

| 파일 | 하는 일 |
| --- | --- |
| `load_scores.py` | 성적 CSV 읽기 및 유효성 검사 |
| `scores.csv` | 정상·오류 데이터가 섞인 실습 입력 |
| `empty.csv` | 헤더만 있는 입력 |
| `weird.csv` | 추가 이상 데이터 입력 |
| `helpers.py` | 경계값 테스트용 CSV 작성 도우미 |
| `test_load_scores.py` | 기본 검증 및 오류 입력 테스트 |
| `test_ai_A.py` | 구현 코드를 제공해 생성한 AI 테스트 |
| `test_ai_B.py` | 명세를 제공해 생성한 AI 테스트 |
| `bug3_logic.py` | 논리 오류 검출 실험용 프로그램 |
| `test_bug3_logic.py` | 논리 오류를 검출하는 AI 생성 테스트 |
| `prompts.txt` | 10주차 실습 프롬프트 원문 |
| `명세서.md` | 배포 명세를 바탕으로 보완한 함수 명세 |
| `실험기록.md` | 실행 결과, 커버리지, 비교 해석 |
| `README.md` | 설치·실행·테스트 안내 |
| `.gitignore` | 캐시 및 임시 파일의 Git 등록 방지 |

## ⑥ 만든 사람 · AI를 어디에 썼는지
